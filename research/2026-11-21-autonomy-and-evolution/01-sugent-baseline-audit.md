## Executive Summary

Sugent has implemented and unit-tested a substantial, zero-intrusion autonomy and governance library in `src/sugent/` (48 files totaling 22,748 lines; 47 modules excluding `index.ts` = 22,701 lines). Live verification run at baseline confirms all declared checks pass on `HEAD`:
- `npm run typecheck` (`tsc -p tsconfig.json --noEmit`): exited `0`.
- `npm run test:sugent`: 37 test files passed, 150 tests passed (`9.72s`).
- `npm run verify:sugent`: `typecheck`, `build` (emitting `dist/sugent-build-manifest.json`), `scripts/verify-sugent.mjs` (18 contract assertion blocks), and `npm run docs:check` (0 errors, 0 warnings) all exited `0`.

However, primary-source cross-checking reveals a critical distinction between **library completeness** and **live closed-loop runtime autonomy**:
1. **Runtime Wiring Gap:** Several deterministic Sugent primitives (`evaluatePersonalTrigger`, `createEnvelopedRuleEventSink`, `TriggerCoalescer`, `AntigravityHookSink`, `scanCadence`/`drainMorning` background loops) are unit-tested in isolation yet remain **unwired** from `App` / `TaskService` / `BotRuntime` daemon loops.
2. **Planned-Only Artifacts:** `src/sugent/memory-gardener.ts`, `src/sugent/external-agents.ts`, 3 of 8 `PersonalSourceKindId` adapters (`filesystem`, `mail_calendar`, `webhook`), and Electron's `globalShortcut`/`Tray` dropzone hooks do **not** exist in code.
3. **Five Structural Bottlenecks:** Even where modules are wired, Sugent lacks (i) cross-model edit-rationale & outcome attribution, (ii) continuous pre-LLM surprise/salience scoring, (iii) unified offline memory consolidation (compounded by a split dual-KG bug), (iv) goal/budget-aware executive focus arbitration across concurrent tickets, and (v) automated post-edit regression rollback.

## 2. Current Autonomy & Self-Evolution Mechanisms

### 2.1 Trigger Gating, Hop Circuit Breaker & `observe -> act` Promotion

- **Pure Intake-to-Eval Gate (`src/sugent/kernel.ts:52-142`):** `evaluatePersonalTrigger(trigger, ctx)` is statically guarded for zero I/O, zero clocks, zero RNG, and zero vendor strings (`test/sugent-proactive-cadence.unit.test.ts` mirrors this purity pattern; `kernel.ts:7-10`). Gate precedence is strictly deterministic:
  1. `!trigger.fromAllowedSender` -> `ignore_noise` (`unlisted_sender`, 0 LLM tokens, `:56-66`).
  2. `hopCount > maxHops` (`DEFAULT_MAX_HOPS = 8` at `:16`) -> `halt_circuit_breaker` (`hop_limit_exceeded`, `requiresOwnerAlert: true`, `:68-79`).
  3. `ctx.activeTicketIdForThread && trigger.addressedToAgent` -> `attach_ticket` (`thread_followup`, `:81-92`).
  4. `trigger.addressedToAgent` -> `accept_act` (`explicit_owner_request`, role `computer_use` or `executor`, `:94-104`).
  5. Unaddressed event -> matches first rule with `mode !== "off"` in `ctx.matchingRules`: `act` -> `accept_act`, `observe` -> `accept_observe` (role `assessor`, shadow `would` logging only), else `ignore_noise` (`:106-141`).
- **Unforgeable Hop Monotonicity:** Downstream triggers cannot reset `hopCount`: `deriveChildTriggerHop` (`kernel.ts:148-160`) increments `hopCount + 1` and preserves `originTriggerId`; `materializeReceiptFollowups` (`receipt-protocol.ts:248-306`) propagates `childHop` to both `later` self-wakeups and `events`; `SuspendedRoundStore` (`receipt-protocol.ts:330-430`) persists `hopCount` across zero-cost disk suspend/resume; `TriggerCoalescer.completeAndDrain` (`sources.ts:427-461`) takes `maxHop` across queued events. Only `resetHopChainByOwner` (`kernel.ts:165-179`) resets to `0`.
- **Two Separate `observe -> act` Promotion Paths:**
  1. *Host Rules (`src/tasks/rules.ts:18`, `src/tasks/service.ts:2881-2915`):* `TaskService.suggestItem()` scans `ruleRuns(rule.id, { mode: "observe", outcome: "done", version: rule.version, limit: RULE_SUGGEST_AFTER })` (`RULE_SUGGEST_AFTER = 3`). Reaching 3 successful runs on the current rule version surfaces a UI suggestion in Needs You (`actions: ["act", "dismiss"]`); dismissing via `keepObserving()` records `SUGGEST_SEEN + rule.id` for `rule.version`. Meanwhile `kernel.ts:185-189` provides the pure predicate `shouldSuggestRulePromotion()`.
  2. *Stewardship Trust Ladder (`src/sugent/stewardship-ledger.ts:15,36-40,424-538`):* `RelationshipProfile.trustTier` steps through `L0_record_only` -> `L1_whisper_prompt` -> `L2_suspend_approval` -> `L3_shadow_autonomous`. `recordVerifiedObservation()` (`:465-487`) increments `verifiedObservations` and checks `shouldSuggestRulePromotion()` against `TRUST_PROMOTE_THRESHOLD = 3`. `promoteTrustTier()` (`:490-506`) throws `TRUST_PROMOTION_DENIED` unless `verifiedObservations >= 3 && ownerConfirmed === true`. Instant demotion works via `downgradeTrustTier()` (`:509-530`) or natural-language `applyOwnerTrustDirective()` (`:533-538`).

## 3. Five Concrete Bottlenecks Blocking Closed-Loop Continual Autonomy & Self-Evolution

### Bottleneck 1: Zero Structured Edit-Rationale, Prediction & Cross-Model Outcome Attribution Across BYOK Switches

- **Primary Evidence:**
  - `src/sugent/gateway.ts:12-75` and `src/sugent/provider-registry.ts:361-421` (`setRoleRouting`) bind static model strings to the 4 roles (`assessor`, `executor`, `computerUse`, `steward`). When a user switches BYOK providers (e.g., DeepSeek -> Claude -> Ollama -> Gemini), no rationale or expected outcome contract is recorded per edit or routing change.
  - `src/sugent/causal-ledger.ts:26-48` (`CausalFactInput`) records `modelRole` (`:42`), `outcome` (`"done" | "failed" | "stopped"`, `:39`), and `costUsd` (`:46`), **but has zero fields for `modelId`, `providerId`, `editRationale`, `predictedOutcome`, `observedOutcomeDelta`, or `errorCluster`**.
  - `src/sugent/steward-llm-agent.ts:634-642`: `runTurn()` receives `data.model` (`:650`) yet never logs `modelUsed` to `CausalLedger` or `StewardshipLedger`, and computes usage with a hardcoded formula `((prompt_tokens * 3 + completion_tokens * 15) / 1_000_000)` (`:640`) regardless of actual BYOK model pricing in `model-catalog.ts` / `byok-diagnostics.ts`.
  - `src/sugent/self-evolution.ts:27-34` (`SelfEvolutionPlan`) tracks only `{ goal, baseCommit, touchedFiles, assessments, overallRisk, verificationCommand }`—no hypothesis, success metric, or model attribution. `src/sugent/capability-awareness.ts:38-43` (`EvolutionRecord`) logs only `{ buildId, version, recordedAtIso, highlights }`. `src/sugent/vibe-coding-pipeline.ts:191,480-516` leaves `causalLedger` unused and discards raw `failLogs` (`outputTail`) after `maxVerifyRetries = 2` without structured failure clustering.
- **Blocking Impact:** Sugent cannot learn across BYOK model switches which provider/model fails on specific edit categories, why a past self-edit succeeded or regressed, or whether a change improved real outcomes over baseline predictions.

### Bottleneck 2: Missing Pre-LLM Cognitive Surprise / Salience Scoring Between 0-Token Probes and `assessor`

- **Primary Evidence:**
  - `src/sugent/sources.ts:329-397` (`ZeroTokenProbeTracker.evaluate`) and `src/sugent/antigravity-bridge.ts:729-744` (`AntigravityStateReader.scan`) decide whether to wake the agent via **binary SHA-256 hash inequality** (`prev.digest !== digest` with `wakeOnDiff: true`). Any trivial diff (minor step increment, log reordering, timestamp drift) triggers `shouldWakeAgent: true` (`diff_detected`) without scoring magnitude, novelty, urgency, or goal relevance.
  - Downstream classification relies on brittle static regexes rather than calibrated salience: `UniversalDropzone.classifyDropzoneIntent()` (`src/sugent/universal-dropzone.ts:143-177`) uses regexes (`ADVISE_RE`, `CAPTURE_EXPLICIT_RE`, `RECALL_RE`, `DELEGATE_TASK_RE`); `ArtifactComprehensionPipeline` `deterministicSynthesize()` (`src/sugent/antigravity-artifacts.ts:264-266`) checks tombstones by an exact 8-character prefix slice (`gr.statement.slice(0, 8)`).
  - `src/sugent/proactive-cadence.ts:302-338` uses binary threshold checks (`stalledDays >= thresholdDays`, `diffMs <= leadDays`), emitting flat priority buckets (`urgent` vs `normal`) with no continuous salience ranking when multiple signals compete under the 2/day quota.
- **Blocking Impact:** Between binary 0-token hash checks and full LLM (`assessor` / `steward`) calls, there is an all-or-nothing cliff: noisy diffs waste tokens or saturate the 2/day proactive cap, while subtle high-surprise semantic shifts (e.g., diverging goals or repeated soft failures) fail to score above threshold.

### Bottleneck 3: Missing Offline Consolidation Loop (`memory-gardener.ts`) & Fragmented Knowledge Graphs

- **Primary Evidence:**
  - `src/sugent/memory-gardener.ts` **does not exist**; no periodic offline job consolidates `walkthrough.md` artifacts, `SuspendedRoundStore` / `VibeCodingPipelineOrchestrator` rejections, or repeated tool failures into `.agents/rules/`, `TOMBSTONES.md`, or cross-project KG edges.
  - **Dual-Store Split:** `App` creates `SugentKnowledgeGraph` at `<dataDir>/sugent-kg` (`src/app.ts:219`) for `StewardshipLedger`, `UniversalDropzone`, `SugentP2HostService` E2EE sync, and `CapabilityAwarenessEngine`. `AgentManager` creates an isolated `SugentKnowledgeGraph` at `<dataDir>/knowledge-graph` (`src/agent/manager.ts:218`), and `prepareSelfEvolutionWorkspace()` also opens `<dataDir>/knowledge-graph` (`src/sugent/self-evolution.ts:630`).
  - **Broken Pruning in `ingestMemoryReviewOps` (`src/sugent/knowledge-graph.ts:241-285`):** Although the method signature accepts `ops: { add, remove }` and its docstring promises weakening/removing deleted entries (`:239`), the implementation (`:256-284`) **never reads `ops.remove`**. Only `ops.add` is processed; there is no temporal decay, weight pruning, or cross-session contradiction detection.
  - `StewardHostService.scanCadence` (`steward-host-service.ts:946`) has no weekly `App` timer (`src/app.ts:980-1028`), so `periodic_calibration` (`proactive-cadence.ts:315-333`) never runs autonomously.
- **Blocking Impact:** Conversational workflows crystallized in `<dataDir>/knowledge-graph` are invisible to 5D Stewardship / E2EE sync (`<dataDir>/sugent-kg`), stale facts accumulate unpruned, and rejected plans never auto-crystallize into falsification tombstones.

### Bottleneck 4: Missing Executive Focus, Goal-Aware Priority & Resource Arbitration Across Concurrent Tickets

- **Primary Evidence:**
  - Host `TaskService` scheduling (`src/tasks/slots.ts:9-63`, `pickRuns`) arbitrates runs solely via 4 coarse FIFO priority tiers (`person > launch > recover > rule`) with static slot caps (`DEFAULT_TASK_SLOTS = 2` per bot, `DEFAULT_MAX_BACKGROUND = 4` global, `MAX_WORKING_TASKS = 10` in `src/tasks/service.ts:101`). It never queries `StewardshipLedger.goals` (`MAX_ACTIVE_GOALS = 3`), `ResourceEntry` (`time_window` / `budget_cap`), or owner cognitive focus.
  - Meanwhile `VibeCodingPipelineOrchestrator.startTask()` (`src/sugent/vibe-coding-pipeline.ts:290-407`) and `AntigravityDispatcher.startNewSession()` (`src/sugent/antigravity-dispatcher.ts:266-297`) dispatch external coding sessions directly via `agentapi` without acquiring `TaskService` slots, consulting `TriggerCoalescer` (`src/sugent/sources.ts:404-462`, 0 host callers), or checking active North Star alignment.
  - Multiple pending pipelines in `vibe-pipelines.json` collide at UI/IM reply routing (`VibeCodingPipelineOrchestrator.findPendingApproval()` at `vibe-coding-pipeline.ts:244-246` returns only the single most-recent pending pipeline when `pipelineId` is omitted).
  - Cost accounting is fragmented: `TaskService` estimates run cost via `cost.ts`, `LocalBudgetLedger` checks per-bot monthly reserve (`src/app.ts:393-394`), while `StewardLlmAgent` charges flat `$3/$15` per 1M tokens to `"default"` (`steward-llm-agent.ts:640`, `src/app.ts:271`), and `AntigravityDispatcher` subprocess token costs are untracked (`causal-ledger.ts` receives zero `costUsd`).
- **Blocking Impact:** Background rules, concurrent `VibeCoding` worktrees, and Antigravity sessions compete unchecked for CPU, API budget, and owner attention without a unified executive arbiter enforcing North Star focus or deferring low-priority work.

### Bottleneck 5: No Automated Post-Edit Behavioral Regression Detection or Outcome-Triggered Rollback

- **Primary Evidence:**
  - Current safety gates stop at **pre-execution / boot liveness**:
    1. `amb-self-edit-gate.mjs` and `assessSelfEditPath()` (`self-evolution.ts:492-552`) gate file paths statically before write.
    2. `IndependentGateRunner.run()` (`vibe-coding-pipeline.ts:120-154`) runs `verifyArgv`/`smokeArgv` once before packaging (with up to `maxVerifyRetries = 2` blind retries, `:216`).
    3. `SafeRelaunchCoordinator` + `scripts/safe-relaunch.mjs:104-144` monitor **process startup liveness only**: if `boot-healthy.json` (`startedAtMs >= swapStartedAtMs`) appears within `30_000`ms (`safe-relauncher.ts:189`, `electron/main.ts:416-420`, call at `:418`), the transaction is marked `"succeeded"` permanently.
  - Once live, there is **zero automated post-edit outcome delta evaluator** over `CausalLedger`, `TaskService` run failure rates, `approval_decided` rejections, or `downgradeTrustTier` events:
    - Faulty `L1_extension_hotplug` plugins (`<dataDir>/self-repo/extensions/plugins/*.mjs`) or crystallized skills (`knowledge-graph.ts:409-421`, `vibe-coding-pipeline.ts:443-462`) cannot be selectively quarantined/reverted upon runtime regression; `resetSelfEvolutionOverlay()` (`self-evolution.ts:460-466`) is a manual all-or-nothing wipe of `extensions/`.
    - Promoted rules that degrade after entering `act` mode only auto-pause after `RULE_FAILS_TO_PAUSE = 3` consecutive failures (`src/tasks/rules.ts:14`) without automatically demoting `act -> observe`, reverting the associated self-edit commit/plugin, or minting a `ValueGuardrail` tombstone.
- **Blocking Impact:** Silent behavioral regressions (higher cost, lower task success, increased owner rejections, noisy false-positive rule runs) after an edit or skill crystallization persist indefinitely until manual human intervention.
